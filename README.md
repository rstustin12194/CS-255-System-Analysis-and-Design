# CS-255-System-Analysis-and-Design
# Project Overview
This repository contains two projects from CS 255: System Analysis and Design. Project One is a Business Requirements Document, and Project Two is a System Design Document. Together, they demonstrate the process of understanding a client's needs and planning a software system to meet those needs.

# Project Reflection
# Briefly summarize the DriverPass project. Who was the client? What type of system did they want you to design?
DriverPass was the client for this project. The company wanted a web-based system to help students prepare for driving tests through training packages, practice tests, and driving lessons. The system needed to let customers manage appointments online while also allowing employees to schedule lessons, manage accounts, track student progress, and maintain records. DriverPass also wanted the system to work on computers and mobile devices and to provide appropriate access for different types of users.

# What did you do particularly well?
I think I did particularly well at organizing the client's needs into clear functional and nonfunctional requirements. I was able to identify important features, such as scheduling driving lessons, tracking practice-test results, and controlling access based on user roles. I also worked on connecting those requirements to the UML diagrams in the system design document so the diagrams represented how the proposed system would work.

# If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?
If I could revise one part, I would focus on the UML diagrams in the System Design Document. I would make the relationships and steps even clearer and review each diagram against the business requirements to ensure nothing important was left out. I would also ask for feedback from someone unfamiliar with the project to see whether the diagrams communicate the system's behavior effectively.

# How did you interpret the user's needs and implement them into your system design? Why is it so important to consider the user's needs when designing?
I interpreted the client's needs by reviewing the DriverPass interview and separating the requested features from the system's technical and security requirements. For example, the need to book driving lessons became a scheduling process that connects a customer, driver, vehicle, and available time. The different responsibilities of customers and employees became separate user roles and permissions. Considering user needs is important because a system can be technically functional but still fail if it does not solve the problems its users actually face.

# How do you approach designing software? What techniques or strategies would you use in the future to analyze and design a system?
My approach is to understand the problem and the people using the system before deciding how to build it. I would start by gathering requirements, identifying the main users, and separating essential features from future improvements. Then I would use tools such as use case, activity, sequence, and class diagrams to visualize the system from different perspectives. In future projects, I would also review designs with stakeholders, check for missing requirements, and revise the models before development begins. This would help reduce misunderstandings and make the finished system more useful.
